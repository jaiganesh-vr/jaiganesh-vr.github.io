Planning Patterns for Agents: ReAct, Plan-and-Execute, Reflection

AI Agents Patterns

Apr 04, 2026

Giving a model tools is only half of building an agent. The other half is deciding how it reasons about which tool to use, in what order, and when to stop. A few patterns have emerged as reliable starting points.

ReAct: Reason, Then Act

ReAct interleaves short reasoning steps with actions. The model writes a thought about what it knows and needs, calls a tool, reads the observation, and writes the next thought.

  • Strength: adapts immediately to what each tool returns.
  • Weakness: no overall plan, so long tasks can wander or loop.

ReAct is the default shape of most tool-using agents today, and for tasks of a handful of steps it is hard to beat.

Plan-and-Execute

Plan-and-execute separates the two jobs. A planning step produces an explicit list of sub-tasks. An executor works through them one by one, and the planner revises the list when results change the picture.

  • Strength: keeps long tasks on track, and the plan can be shown to a person before work starts.
  • Weakness: plans made early are based on little information and can be confidently wrong.

A plan is a hypothesis about the task. Good agents treat it that way.

Reflection

Reflection adds a review step. After producing an answer or finishing an attempt, the agent critiques its own output against the goal and tries again with that critique in context.

  • Strength: catches errors that are obvious on a second read, especially in code and writing.
  • Weakness: a model reviewing its own work shares its own blind spots, and extra rounds add cost.

Reflection works best when the critique is grounded in something external: test results, a validator, a checklist or a separate reviewer.

Combining Them

These patterns compose. A common shape is a plan, executed step by step with ReAct, with a reflection pass at checkpoints. Reasoning models, which think at length before answering, have also absorbed some of this structure into the model itself.

Choosing a Pattern

  • Short, exploratory tasks: ReAct.
  • Long tasks with clear sub-goals: plan-and-execute.
  • Tasks with verifiable output: add reflection driven by real checks.

Closing Thought

The pattern matters less than the feedback it gives the agent. Every reliable design gives the model a way to notice it is wrong before the user does.
