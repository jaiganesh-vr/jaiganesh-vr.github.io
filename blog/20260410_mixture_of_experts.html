Mixture of Experts: Bigger Models, Same Compute

Machine Learning Architecture

Apr 10, 2026

For a dense transformer, every parameter participates in processing every token. Doubling the parameters roughly doubles the compute per token. Mixture of experts breaks that link by activating only a fraction of the model at a time.

The Idea

In an MoE transformer, the feed-forward block in each layer is replaced by several parallel feed-forward networks, called experts, plus a small router.

  • For each token, the router scores every expert.
  • Only the top few experts, often two, process that token.
  • Their outputs are combined, weighted by the router's scores.

A model like Mixtral 8x7B has eight experts per layer and routes each token to two of them. It holds far more parameters than it uses on any single token.

Total parameters set what the model can store. Active parameters set what each token costs.

Why This Matters

MoE lets a model grow its capacity without growing its per-token compute in proportion. In practice, MoE models often match dense models with similar total parameter counts while running at the speed of much smaller ones.

This is why many recent frontier and open-weight models use sparse expert layers.

What the Experts Learn

The name suggests clean specialists for topics like biology or law. In practice, routing tends to specialise along more mechanical lines, such as particular token types, syntax patterns or positions. Experts are better thought of as learned partitions of the computation than as human-readable domains.

The Trade-offs

  • Memory: every expert must be loaded, even if few are used per token, so MoE models need a lot of memory.
  • Load balancing: routers can collapse onto a few favourite experts. Training adds auxiliary losses or balancing mechanisms to spread the load.
  • Serving complexity: experts are often spread across devices, adding communication overhead.
  • Fine-tuning: sparse models can be less stable to adapt than dense ones.

Where It Fits

MoE is most attractive when serving at scale, where memory can be amortised across many requests and compute per token drives cost. For small local deployments, a dense model of similar active size is often simpler.

Closing Thought

Mixture of experts is conditional computation made practical. Not every part of a model needs to think about every token, and exploiting that has become one of the main levers for scaling efficiently.
