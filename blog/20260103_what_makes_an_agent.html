What Actually Makes a System an Agent

AI Agents Systems

Jan 03, 2026

Few words in AI have been stretched as far as agent. It gets attached to chatbots, scripted workflows, browser extensions and research prototypes alike. When a word means everything, it stops helping anyone make design decisions.

A more useful definition is narrow: an agent is a system where a language model decides what to do next, takes an action through a tool, observes the result, and repeats until the goal is met or it gives up.

Why This Matters

The difference between a workflow and an agent is who owns the control flow. In a workflow, the developer writes the steps and the model fills in the blanks. In an agent, the model chooses the steps.

That single shift changes everything downstream: how you test the system, how you bound its cost, and how you explain its behavior when something goes wrong.

A workflow fails in predictable places. An agent fails wherever it decided to go.

The Core Loop

Almost every agent, however sophisticated, reduces to the same loop:

  • Observe: read the goal, the conversation and the results of previous actions.
  • Decide: choose a tool to call, or decide the task is finished.
  • Act: execute the tool call outside the model.
  • Update: append the result to the context and go around again.

The intelligence lives in the decide step. Everything else is ordinary software: tool implementations, state management, retries and logging.

Autonomy Is a Dial, Not a Switch

It helps to think of autonomy as a spectrum. At one end, the model classifies a request and routes it. In the middle, it picks from a small set of tools with a human approving each step. At the far end, it plans multi-step work, runs for minutes or hours, and reports back.

Moving along that dial buys flexibility at the price of predictability. Many production systems that are marketed as agents deliberately sit near the middle, and that is usually the right call.

When Not to Build One

If the steps of a task are known in advance, a workflow is cheaper, faster and easier to debug. Agents earn their complexity when the path depends on what is discovered along the way: investigating a bug, researching a question, or navigating a system with many possible states.

A simple test is to ask whether you could draw the flowchart. If you can, write the flowchart as code and use the model inside its boxes.

Closing Thought

The interesting question is not whether something qualifies as an agent. It is how much decision-making you are willing to hand to a model, and what you have put in place to catch it when it decides badly.
