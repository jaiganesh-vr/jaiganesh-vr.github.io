Rerankers: The Missing Step in Retrieval

Machine Learning Retrieval

Sep 01, 2026

Most RAG pipelines retrieve documents with embedding search and pass the top results straight to the language model. Adding one more step, a reranker, is often the single biggest improvement in answer quality.

Two Kinds of Encoder

Embedding search uses a bi-encoder. The query and each document are turned into vectors separately, and relevance is a similarity between vectors. Because documents are encoded ahead of time, searching millions of them is fast.

The cost is that the query and document never meet. Each is compressed into a single vector without knowing what the other contains, so subtle relevance is lost.

A cross-encoder takes the query and a document together as one input and outputs a relevance score. Every word of the query can attend to every word of the document. It is far more accurate, and far too slow to run against an entire collection.

Bi-encoders find candidates. Cross-encoders judge them.

Retrieve, Then Rerank

The two are combined in stages:

  • Retrieve a generous candidate set, perhaps 50 to 200 documents, with embedding or hybrid search.
  • Score each candidate against the query with a cross-encoder.
  • Pass only the top few, perhaps 5 to 10, to the language model.

The first stage optimises recall: do not miss the right document. The second optimises precision: put it at the top.

Why It Helps So Much

Language models answer better from a few highly relevant passages than from many loosely related ones. Irrelevant context dilutes attention and invites the model to use the wrong source. Reranking improves the quality of exactly the tokens that reach the model.

Practical Considerations

  • Latency: reranking 100 candidates adds noticeable time, so batch the pairs and tune candidate counts.
  • Model choice: dedicated reranker models are small and fast. Using a general LLM as a reranker is more flexible but more expensive.
  • Domain fit: rerankers trained on web search may need fine-tuning for legal, medical or code retrieval.
  • Evaluation: measure retrieval with metrics like recall at k and nDCG, separately from answer quality.

Closing Thought

Reranking is a classic search engine technique that RAG systems rediscovered. It costs little to add and directly improves the evidence a model reasons from.
