Constrained Decoding with Grammars

Algorithms Decoding

Jul 27, 2026

Asking a model nicely to return valid JSON works most of the time. Most of the time is not enough for software that parses the result. Constrained decoding makes invalid output impossible rather than unlikely.

The Core Idea

At each step, a language model produces a probability for every token in its vocabulary. Constrained decoding adds a filter before sampling:

  • Track where generation currently is in the target format.
  • Determine which tokens could legally come next.
  • Set the probability of every other token to zero.
  • Sample from what remains.

The model still chooses what to say. The grammar decides what it is allowed to say.

From Schema to Automaton

The format is usually given as a regular expression, a JSON Schema or a context-free grammar. These are compiled into a state machine: for regular expressions, a finite automaton; for nested structures like JSON, a pushdown automaton that tracks open brackets.

At each step, the current state determines the set of valid next characters.

The Token Problem

Grammars are defined over characters, but models produce tokens, and a single token may span several characters, such as a quote followed by a letter. For each state, the decoder must work out which tokens are valid as complete character sequences.

Checking the entire vocabulary at every step would be slow, so implementations precompute, for each automaton state, a mask of allowed tokens. With that index built in advance, constraining a step costs little more than applying a mask.

What It Guarantees and What It Doesn't

  • Guaranteed: syntactically valid output that matches the schema, every time.
  • Not guaranteed: correct values. A field can be valid JSON and still wrong.
  • Possible side effect: if the model wanted to write something the grammar forbids, forcing it down an unlikely path can reduce quality.

Good practice is to let the format be reasonably natural for the model, such as allowing a reasoning field before the answer field.

Where It's Used

Structured output features in model APIs, open-source libraries for local models and tool calling implementations all use variants of this technique to ensure arguments parse correctly.

Closing Thought

Constrained decoding turns a soft request into a hard guarantee. It is a small piece of classic computer science, automata theory, applied at exactly the point where model output meets traditional software.
