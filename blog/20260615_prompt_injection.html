Prompt Injection and the Agent Security Problem

AI Agents Security

Jun 15, 2026

A language model reads instructions and data in the same channel: text in its context. It has no reliable way to tell a developer's instruction from a sentence inside a web page it was asked to summarise. Prompt injection exploits exactly that.

Direct and Indirect Injection

  • Direct injection: a user types instructions meant to override the system prompt, such as asking the model to ignore its rules.
  • Indirect injection: malicious instructions hide in content the agent processes, like an email, a document, a web page or a tool result.

Indirect injection is the bigger threat for agents, because the attacker never talks to the agent directly. They only need to put text somewhere the agent will read it.

An agent that reads the internet is taking instructions from the internet.

Why It Is Hard to Fix

Unlike SQL injection, there is no equivalent of parameterised queries. Models can be trained to resist injected instructions, and they have become much better at it, but resistance is statistical. A defence that blocks 99 percent of attempts still fails when an attacker can try thousands of variations.

The Dangerous Combination

Injection becomes serious when one agent has all three of these:

  • Access to private data, like email, files or internal systems.
  • Exposure to untrusted content, like web pages or inbound messages.
  • A way to communicate externally, like sending email or making web requests.

With all three, injected text can instruct the agent to collect private data and send it out. Removing any one of the three breaks the attack.

Designing Around It

  • Least privilege: give each agent only the tools and data its task needs.
  • Separate trust levels: an agent that reads untrusted content should not hold powerful tools; it can pass structured, validated results to one that does.
  • Human confirmation: require approval for consequential actions, like sending messages, payments or deletions.
  • Constrain outputs: limit where the agent can send data, for example allow-listing domains.
  • Monitor: log tool calls and flag unusual patterns.

Closing Thought

Prompt injection is less a bug in models and more a property of systems that mix trusted instructions with untrusted data. Until models can separate the two perfectly, safety has to come from the architecture around them.
