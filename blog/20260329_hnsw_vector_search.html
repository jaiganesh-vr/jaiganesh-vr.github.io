HNSW: How Vector Search Stays Fast

Algorithms Retrieval

Mar 29, 2026

Retrieval systems store documents as embedding vectors and answer a query by finding the vectors closest to it. With a few thousand documents, you can compare against every one. With hundreds of millions, exact search becomes too slow for interactive use.

Approximate nearest neighbour search trades a little accuracy for a huge speedup. HNSW is the most widely used algorithm for it.

Navigable Small Worlds

The starting idea is a graph where each vector is a node connected to some of its near neighbours. To search, you start at an entry node and repeatedly move to whichever neighbour is closest to the query, stopping when no neighbour is closer.

If the graph also contains some long-range links, this greedy walk reaches the right region in surprisingly few hops, the same way any two people are connected through a short chain of acquaintances.

Adding Hierarchy

HNSW, short for Hierarchical Navigable Small World, stacks several such graphs in layers:

  • The top layer contains very few nodes with long links, like a motorway network.
  • Each lower layer contains more nodes with shorter links.
  • The bottom layer contains every vector.

A search starts at the top, greedily moves close to the query, then drops down a layer and continues from there. Each layer refines the position, so the total work grows roughly logarithmically with the dataset size.

Coarse to fine: cross the country on the motorway, then take local roads.

The Parameters That Matter

  • M: how many links each node keeps. More links improve recall but cost memory.
  • efConstruction: how widely to search when inserting a node. Higher builds a better graph, more slowly.
  • efSearch: how many candidates to keep during a query. This is the main dial between speed and recall.

Trade-offs

HNSW delivers excellent recall at low latency, which is why most vector databases support it. Its costs are memory, since the graph and vectors usually live in RAM, and deletions, which leave holes in the graph that need periodic repair.

For very large collections, it is often combined with quantization to shrink vectors, or replaced with disk-friendly indexes.

Closing Thought

Vector search feels like a database feature, but underneath it is a clever graph algorithm. Knowing its dials explains why retrieval quality sometimes changes when nothing in the model did.
