Tool Calling: How Language Models Use Functions

AI Agents LLMs

Jan 26, 2026

A language model only produces text. It cannot query a database, send an email or check today's weather. Tool calling is the mechanism that lets it ask the surrounding application to do those things on its behalf.

It is the foundation every agent is built on.

How It Works

The application describes each available tool to the model: a name, a plain-language description and a schema for its arguments, usually JSON Schema. The model then decides, as part of its normal output, whether to respond directly or to request a tool.

  • The model emits a structured request: tool name plus arguments.
  • The application validates the arguments and runs the actual function.
  • The result is passed back to the model as a new message.
  • The model continues, either calling another tool or answering.

The model never executes anything. It asks, and your code decides.

Why This Matters

That separation is what makes tool calling safe to build on. The application keeps full control over what runs, with what permissions and with what limits. A model can request a file deletion, but only the application can perform one.

It also means the quality of an agent depends heavily on code that has nothing to do with the model: input validation, error messages, timeouts and permission checks.

Designing Good Tools

Models choose tools by reading their descriptions, so tool design is closer to API documentation than to programming.

  • Name tools clearly. A name like search_orders beats a generic query tool.
  • Describe when to use it, not only what it does. Include what it returns and its limits.
  • Keep arguments few and typed. Enums and required fields reduce guessing.
  • Return useful errors. "Customer ID not found, expected format C-12345" lets the model recover. A stack trace does not.

Fewer, Better Tools

Giving a model fifty overlapping tools makes selection harder and fills the context with descriptions. A smaller set of well-scoped tools almost always performs better than a large set of thin wrappers around every endpoint.

A good rule of thumb is to design tools around tasks a person would describe, not around the shape of your internal APIs.

Closing Thought

Tool calling turns a model from something that talks about the world into something that can act in it. The model provides judgment, but the reliability comes from how carefully the tools around it are built.
