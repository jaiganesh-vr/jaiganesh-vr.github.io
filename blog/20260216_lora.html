LoRA: Fine-Tuning Without Touching Most of the Model

Machine Learning Fine-Tuning

Feb 16, 2026

Fully fine-tuning a large language model means updating every one of its billions of weights, storing gradients and optimizer state for all of them, and saving a complete copy of the model for every task. For most teams, that is not practical.

Low-rank adaptation, or LoRA, changes the economics by training a tiny fraction of the parameters.

The Core Idea

LoRA freezes the original weights. For selected weight matrices, it adds a small trainable update made of two thin matrices:

W' = W + B·A

If W is d × d, A is r × d and B is d × r, where the rank r is small, often 8 to 64. The update B·A has the same shape as W, but it is described by far fewer numbers.

B is initialised to zero, so at the start of training the model behaves exactly like the original.

Why So Few Parameters Work

The hypothesis behind LoRA is that the change needed to adapt a pre-trained model to a new task has low intrinsic rank. The model already knows language. Adapting it is a nudge in a few directions, not a rewrite.

Empirically this holds well. For many tasks, LoRA matches full fine-tuning while training well under one percent of the parameters.

Practical Benefits

  • Memory: gradients and optimizer state are only needed for the small matrices.
  • Storage: an adapter is megabytes, not gigabytes, so you can keep many of them.
  • Swapping: one base model can serve several adapters, switching per request.
  • No inference cost: the update can be merged back into W after training.

QLoRA pushes this further by keeping the frozen base model in 4-bit precision while training adapters in higher precision, which brings fine-tuning of large models within reach of a single GPU.

Things to Watch

LoRA lowers the cost of training. It does not lower the cost of good data.

Rank, learning rate and which layers to adapt all matter, and the right values depend on the task. Adapters trained on narrow data can also reduce general capability, so evaluation should cover what the model used to do well, not only the new task.

Closing Thought

LoRA is a good example of a simple mathematical observation turning into a large practical shift. Fine-tuning went from a lab-scale project to something an individual engineer can run in an afternoon.
