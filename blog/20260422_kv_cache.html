The KV Cache: Why Generation Gets Faster After the First Token

Algorithms Inference Systems

Apr 22, 2026

A language model generates text one token at a time, and each new token attends to every token before it. Done naively, producing token 1,000 would mean recomputing attention inputs for the previous 999 tokens, then doing it all again for token 1,001.

The key-value cache removes that waste, and in doing so becomes one of the most important data structures in LLM serving.

What Gets Cached

In each attention layer, every token produces a query, a key and a value. For past tokens, the keys and values never change, because a token cannot attend to anything after it.

So after computing them once, the model stores them. When generating the next token, it only computes the new token's query, key and value, appends the new key and value to the cache, and attends over the stored history.

Each step does work for one new token, instead of the whole sequence.

Prefill and Decode

This splits inference into two phases:

  • Prefill: the whole prompt is processed in parallel and the cache is filled. This is compute-heavy and determines time to first token.
  • Decode: tokens are generated one by one, each reading the full cache. This is memory-bandwidth-heavy and determines tokens per second.

That is why the first token often takes noticeably longer than the rest.

The Memory Cost

The cache grows with every token. Its size is roughly:

2 × layers × KV heads × head dimension × tokens × bytes per value

For a large model with long contexts, this reaches many gigabytes per request, often more than the request's share of the model weights. It limits how many users can be served at once and how long their contexts can be.

Shrinking the Cache

Much recent architecture work targets this cost:

  • Grouped-query attention: several query heads share one set of keys and values.
  • Quantized caches: storing keys and values in 8 or 4 bits.
  • Paged allocation: managing cache memory in blocks to avoid fragmentation.
  • Prefix caching: reusing the cache for shared prompt prefixes like system prompts.

Closing Thought

The KV cache turns quadratic recomputation into a growing lookup table. Many decisions about context length, batching and pricing are, underneath, decisions about how to manage this one structure.
