Memory for Agents

AI Agents Systems

Mar 11, 2026

A language model has no memory between calls. Every request starts from zero, and whatever continuity a user experiences is something the application has rebuilt and placed back into the context.

For agents that run long tasks or serve the same person over weeks, designing that memory is one of the most important engineering choices.

Why This Matters

Without memory, agents repeat questions, lose track of decisions and redo work. With careless memory, they recall stale or wrong information with full confidence. Both feel broken to users.

Memory is not storage. It is deciding what to bring back, and when.

Working Memory

The context window is the agent's working memory: the conversation, recent tool results and the current plan. It is fast and precise, but limited, and long tasks eventually overflow it.

Common techniques to manage it:

  • Summarisation: compress older turns into a running summary.
  • Trimming tool output: keep the parts of a large result that matter, not the whole payload.
  • Scratchpads: let the agent write notes or a task list to a file it can re-read.

Long-Term Memory

Information that should survive across sessions lives outside the model:

  • Semantic memory: facts about the user or domain, such as preferences, names and settings.
  • Episodic memory: records of past interactions and what happened in them.
  • Procedural memory: learned instructions about how to do things, often stored as updated system prompts.

These are typically stored in a database and retrieved by key, by recency, or by embedding similarity, then inserted into the prompt.

Writing Is Harder Than Reading

Retrieval gets most of the attention, but deciding what to save is the harder problem. Saving everything creates noise; saving too little loses context. Many systems let the model decide what is worth remembering through an explicit memory tool, and periodically consolidate or expire old entries.

Conflicting memories are another trap. If a user moves city, the agent needs to update the old fact, not store both.

Privacy and Control

Persistent memory about people raises obvious questions. Good designs make memory visible and editable, avoid storing sensitive data without reason, and give users a way to make the agent forget.

Closing Thought

The model supplies reasoning; memory supplies continuity. The agents that feel genuinely helpful over time are usually the ones where memory was designed deliberately rather than bolted on.
