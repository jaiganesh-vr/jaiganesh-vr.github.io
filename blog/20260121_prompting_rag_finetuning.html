Prompting, RAG or Fine-Tuning?

Machine Learning LLMs

Jan 21, 2026

When a general-purpose model does not quite fit a problem, there are three common ways to adapt it: change the prompt, give it retrieved knowledge, or change its weights through fine-tuning. Teams often jump to the most expensive option first.

Each approach changes something different, and knowing which lever moves which behavior saves a lot of wasted effort.

What Each One Changes

  • Prompting changes the instructions. It shapes format, tone and task framing, using only what the model already knows.
  • Retrieval-augmented generation changes the information. It puts relevant, current or private facts into the context at answer time.
  • Fine-tuning changes the model. It adjusts weights so that a behavior, style or skill becomes the default.

A useful shorthand: RAG teaches the model what to say, fine-tuning teaches it how to say it.

Start With Prompting

Prompting is fast to iterate, costs nothing to deploy and is easy to roll back. Clear instructions, a few good examples and an explicit output format solve a surprising share of problems.

If a carefully written prompt gets the behavior right most of the time, the remaining issues are usually about missing knowledge or consistency, which point to the next two options.

Add Retrieval for Knowledge

If the model gives fluent but wrong answers about your domain, the problem is knowledge, not behavior. Fine-tuning is a poor way to inject facts: it is hard to update, hard to audit and prone to blending facts together.

Retrieval keeps knowledge outside the model, where it can be updated, permissioned and cited. When a document changes, the next answer changes with it.

Facts belong in a database. Habits belong in the weights.

Fine-Tune for Behavior

Fine-tuning pays off when you need a behavior that prompting cannot reliably produce: a strict house style, a specialised output format, a narrow classification task, or a smaller model that matches a larger one's performance on a specific job.

It requires good training data, evaluation sets and a plan for retraining when the base model changes. Parameter-efficient methods like LoRA have made it far cheaper, but the data work remains.

They Combine

These are not exclusive. A common production pattern is a fine-tuned model that follows a domain's conventions, prompted with clear instructions, answering from retrieved documents.

Closing Thought

The best order is usually cheapest first: prompt, then retrieve, then fine-tune. Each step should be justified by a specific failure the previous one could not fix.
