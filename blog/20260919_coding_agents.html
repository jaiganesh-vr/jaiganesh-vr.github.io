Coding Agents and the Shape of Software Work

AI Agents Software Engineering

Sep 19, 2026

AI assistance for programming started as autocomplete: suggest the next line, accept or ignore. It has since moved to agents that read an entire repository, make changes across many files, run the tests, and iterate until they pass.

That shift changes not just how fast code is written, but what the work of an engineer looks like.

Why Coding Suits Agents

Software engineering has properties that make it unusually good ground for agents:

  • Rich tools: compilers, linters, test suites and version control provide precise feedback.
  • Verifiable results: code either passes tests or it doesn't, which gives the agent a signal to correct itself.
  • Text everywhere: code, docs, errors and logs are all text a model can read.
  • Easy undo: version control makes most changes reversible.

Feedback loops are what make an agent reliable, and software has the best feedback loops of any domain.

How Coding Agents Work

Most coding agents follow the same loop: explore the codebase to find relevant files, form a plan, edit, run the build and tests, read the errors, and repeat. The quality of results depends heavily on how well the agent can search the code and how good the project's tests are.

What Changes for Engineers

  • More reviewing, less typing: a larger share of time goes into specifying tasks clearly and reviewing changes carefully.
  • Context becomes an asset: projects with clear docs, consistent conventions and instructions for agents get noticeably better results.
  • Tests matter more: a strong test suite is now also the agent's guidance system.
  • Parallel work: engineers can delegate several well-scoped tasks at once and review them as they complete.

The Risks

Agents can produce code that passes tests but is subtly wrong, insecure or hard to maintain. They can also make changes faster than people can review them, which shifts the bottleneck to review. Treating agent output like a pull request from a new teammate, read and questioned rather than rubber-stamped, keeps quality up.

Running agents in sandboxes with limited permissions protects against destructive commands.

Closing Thought

Coding agents do not remove the need for engineering judgment. They move it: less into writing each line, more into deciding what should be built, how it should be checked, and whether the result is actually right.
