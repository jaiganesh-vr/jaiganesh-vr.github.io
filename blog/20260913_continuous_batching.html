Continuous Batching and PagedAttention

Algorithms Inference Systems

Sep 13, 2026

Serving a language model to many users is a scheduling problem. Requests arrive at random times, prompts vary in length, and outputs can be ten tokens or ten thousand. How a server groups this work determines how many users one GPU can handle.

Why Batch at All

During decoding, the GPU spends most of its time loading model weights from memory. Processing one sequence or thirty-two costs nearly the same weight traffic, so batching many sequences together multiplies throughput almost for free.

The Problem With Static Batches

The simple approach collects a batch of requests, runs them together and returns results when all are finished. But sequences finish at different times. A request that needs 20 tokens waits for one that needs 2,000, and its slot in the batch sits idle.

New requests also wait until the whole batch completes, adding latency.

Continuous Batching

Continuous batching, also called iteration-level scheduling, makes batching decisions at every decoding step instead of once per batch:

  • When a sequence finishes, its slot is freed immediately.
  • A waiting request is inserted into that slot on the next step.
  • The batch stays full as long as there is work.

The batch becomes a stream that requests join and leave, not a group that moves together.

This can raise throughput several times over static batching with realistic traffic.

The Memory Problem

Each active sequence needs a KV cache that grows with every token. Early servers reserved a contiguous block for the maximum possible length of each request. Most of that reserved memory went unused, which limited how many sequences could run at once.

PagedAttention

PagedAttention borrows virtual memory from operating systems. The KV cache is split into small fixed-size blocks, allocated on demand as a sequence grows. A table maps each sequence's logical positions to physical blocks, which need not be contiguous.

  • Waste drops to at most one partially filled block per sequence.
  • More sequences fit in memory, so batches can be larger.
  • Sequences sharing a prefix, such as a common system prompt, can share blocks.

Closing Thought

Much of the cost reduction in serving language models came from systems ideas like these rather than from changes to models. Scheduling and memory management decide how much intelligence a GPU can deliver.
