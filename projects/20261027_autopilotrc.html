Autopilot RC: An Autonomous Miniature Car

Computer Vision Neural Networks Robotics

Oct 27, 2026

Autopilot RC is an autonomous agent that drives a miniature radio-controlled car. A neural network steers the car along the track from its camera image, shape-based classifiers detect stop signs and traffic lights and estimate their distance, and an ultrasonic sensor stops the car before it collides with obstacles.

The goal of this project was to build a complete self-driving loop on cheap hardware: sense the world from the car, decide on a computer, and act through the car's own remote. Along the way it also needed a way to develop and test the driving logic without the car on the table, which led to a full simulator.

It is built with Python and OpenCV, running across a Raspberry Pi, a computer, and an Arduino.

Highlights

  • Learned steering — A small neural network (OpenCV MLP, 38400 → 32 → 4) reads the lower half of the grayscale frame and predicts forward, left, or right. It learns from you driving the track with the arrow keys.
  • Sign and light detection — Haar cascade classifiers find stop signs and traffic lights in the frame. A traffic light's colour comes from which lamp is brightest.
  • Distance from a single camera — The distance to a sign or light is estimated from how low it sits in the image, using the camera's calibrated height, tilt, and lens.
  • Collision safety — An ultrasonic sensor on the car overrides everything else and stops the car when an obstacle is closer than 30 cm.
  • Fail-safe controller — The Arduino stops the car if commands stop arriving for 500 ms, so a crashed program or dropped link never leaves the car driving blind.
  • Hardware-free simulator — A fake Arduino, a scripted sensor, and ray-traced dashcam videos with exact ground truth let the whole computer side run, train, and be tested without any devices.

Architecture

Three devices work together. The car only senses, the computer does all the thinking, and the Arduino presses the RC remote's buttons. A Raspberry Pi on the car streams camera frames (320x240 at 10 fps) and ultrasonic distance readings to the computer over Wi-Fi. The computer decides what the car should do and sends a one-byte drive command to the Arduino over USB. The Arduino turns that command into button presses on the remote, which drives the car over radio.

On each frame, the computer decides in this order:

1. If the ultrasonic sensor reads under 30 cm, stop.
2. If a stop sign is detected under 25 cm away, stop for 5 s, then ignore stop signs for 5 s so the car can drive past.
3. If a red traffic light is detected under 30 cm away, stop until it is no longer red.
4. Otherwise, steer forward, left, or right, as the neural network predicts.

Tech Stack

• Computer — Python 3.9+, OpenCV (contrib build for cv2.ml and Haar cascades), NumPy, pyserial, pygame

• Raspberry Pi — Raspberry Pi OS Bookworm, picamera2, gpiozero, HC-SR04 ultrasonic sensor

• Arduino — A sketch that maps serial commands to the remote's right, left, forward, and reverse buttons

• Simulator — Ray-traced video renderer, fake Arduino on a virtual serial port, scripted sensor, ffmpeg

• Tooling — pytest, environment-variable configuration with the AUTOPILOT_RC_ prefix

Getting Started

On the computer, create a virtual environment and install the requirements. On the Pi, clone the repository and install picamera2 and gpiozero from apt, then wire the HC-SR04 trigger to GPIO 23 and echo to GPIO 24 through a voltage divider. Upload the Arduino sketch from the Arduino IDE. Then, from the repository root:

1. Test the controls — python -m autopilot_rc.control_test, then drive with the arrow keys.
2. Collect data — python -m autopilot_rc.collect on the computer and python3 -m pi.stream_client on the Pi. Drive several laps, and keep some recordings aside for testing.
3. Train — python -m autopilot_rc.train, then optionally python -m autopilot_rc.evaluate.
4. Drive — python -m autopilot_rc.driver on the computer, then start the stream and ultrasonic clients on the Pi.

To try it without any hardware, run the simulator instead:

python -m simulator.simulate drive

The Simulator

The simulator replaces each device with a stand-in. The Pi camera becomes a video, image sequence, or webcam; the ultrasonic sensor follows a script of distance:seconds steps; and a fake Arduino on a virtual serial port applies the sketch's own rules, including the 500 ms safety stop and rejection of invalid commands. Each run reports what the programs did and how long the car spent in each state.

A renderer ray-traces a low-mounted toy-car dashcam on a miniature track. Every setting, from camera height and lens to track shape and speed, lives in a JSON config, and the same config always produces the same frames. Each video comes with a ground truth file giving the car's position, heading, speed, and distance to objects on every frame.

Because the ground truth heading labels every frame as left, right, or forward, the steering network can be trained on rendered videos with no one driving. Mirroring the images doubles the data, since a mirrored left curve is a right curve. Five test roads the model has never seen are kept separate to measure how well it generalises.

Design Decisions

  • The car only senses — All the computation runs on the computer, so the Pi stays a simple streamer and the model can be larger than the car could run on its own.
  • Drive through the remote, not the car — The Arduino presses the existing remote's buttons, so the car itself needs no modification beyond the sensors.
  • Fixed priority rules around the network — Safety checks run before the steering network on every frame, so obstacles, stop signs, and red lights always win over a steering prediction.
  • Ignore stop signs after stopping — After a 5 s stop, stop signs are ignored for 5 s; otherwise the car would stop again for the same sign forever.
  • Keep test roads different from training — Re-rendering a training scenario gives identical frames, which proves nothing, so test scenarios use new roads.
  • Every setting is overridable — Any value in the config can be set through an AUTOPILOT_RC_ environment variable, such as running without an Arduino or using a webcam instead of the Pi camera.

Testing

The test suite runs the computer side with no hardware, covering the serial link, the steering network, the driving rules, sign and light detection, and the full pipeline. Video tests train and score the network on rendered scenarios. The full suite takes about 2 minutes, or about 35 s without the video tests.

Not covered by the tests are the Pi's hardware code and the Arduino sketch, which need the real devices. The simulator's camera also uses a wider lens than the real Pi camera, so models trained on rendered videos are for the simulator only.

Conclusion

Building Autopilot RC showed that a self-driving system is far more than its steering model: dividing work between devices, layering safety rules above the learned behaviour, failing safe when links drop, and, above all, having a simulator that makes the system testable without the hardware.
