Heapsort

Algorithms Sorting

Mar 21, 2020

Heapsort combines the best of two sorting algorithms: like merge sort it runs in O(n lg n) time, and like insertion sort it sorts in place. It is built on the binary heap, a data structure that is useful well beyond sorting.

The Binary Heap

A binary heap is an array viewed as a nearly complete binary tree. With zero-based indexing, the node at index i has children at 2i + 1 and 2i + 2, and its parent at (i − 1) // 2. No pointers are needed.

In a max-heap, every node is at least as large as its children. So the largest element is always at the root, index 0.

Max-Heapify

The core operation restores the heap property at node i, assuming its subtrees are already heaps. It swaps the node with its larger child until it is larger than both. 

def sift_down(a, i, n):
    while True:
        largest, l, r = i, 2 * i + 1, 2 * i + 2
        if l < n and a[l] > a[largest]:
            largest = l
        if r < n and a[r] > a[largest]:
            largest = r
        if largest == i:
            return
        a[i], a[largest] = a[largest], a[i]
        i = largest

def heapsort(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):   # build max-heap
        sift_down(a, i, n)
    for end in range(n - 1, 0, -1):       # move max to the end
        a[0], a[end] = a[end], a[0]
        sift_down(a, 0, end)

Sift-down runs in O(lg n), the height of the tree.

Building a Heap in Linear Time

Building a heap calls sift-down on every non-leaf node, from the bottom up. A naive bound is O(n lg n), but most nodes are near the bottom where sift-down is cheap. Summing the actual costs gives O(n).

Half the nodes are leaves and need no work; the expensive nodes near the root are few.

Sorting

Once the array is a max-heap, the largest element is at the front. Swap it with the last element, shrink the heap by one, and sift-down the new root. Repeating this n − 1 times leaves the array sorted in ascending order. Total time: O(n lg n).

Properties

  • In place: only a constant amount of extra memory.
  • Worst case O(n lg n): unlike quicksort, no bad inputs.
  • Not stable: equal elements may change relative order.
  • Cache unfriendly: jumps around the array, so in practice it is often slower than a good quicksort.

Priority Queues

The heap's most common use is as a priority queue, supporting insert, maximum and extract-max in O(lg n). Priority queues schedule jobs, drive event simulations, and power Dijkstra's and Prim's graph algorithms.

Closing Thought

Heapsort is elegant because the data structure does all the work. The heap keeps the largest element at hand, and sorting is just asking for it repeatedly.
