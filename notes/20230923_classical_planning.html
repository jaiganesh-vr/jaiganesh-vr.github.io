Classical Planning

Artificial Intelligence Planning

Sep 23, 2023

Planning is the task of finding a sequence of actions that achieves a goal. Search can do this, but planning uses a structured representation of states and actions, which allows general, domain-independent heuristics.

Representing States and Actions

In classical planning, a state is a conjunction of ground facts, like At(Truck, Depot) ∧ In(Box, Truck). Anything not stated is assumed false.

Actions are described by schemas with preconditions and effects: 

Action: Fly(p, from, to)
  Precondition: At(p, from) ∧ Plane(p) ∧ Airport(from) ∧ Airport(to)
  Effect:       ¬At(p, from) ∧ At(p, to)

The effect lists what becomes true (the add list) and what becomes false (the delete list). Everything else stays the same, which neatly sidesteps the frame problem of stating everything that does not change.

This style comes from STRIPS and is standardised in PDDL, the Planning Domain Definition Language used in planning competitions.

Forward State-Space Search

Forward planning starts from the initial state and applies applicable actions until a goal state is reached. It is straightforward, but the number of applicable actions can be enormous, most of them irrelevant.

Backward Search

Backward, or regression, planning starts from the goal and considers only actions that achieve part of it. Regressing a goal through an action produces the subgoal that must hold before the action. It focuses on relevant actions, but works with sets of states, which makes heuristics harder to design.

Domain-Independent Heuristics

The structured representation allows heuristics that work for any planning problem:

  • Ignore preconditions: every action is applicable, so the heuristic counts how many actions are needed to achieve all goals.
  • Ignore delete lists: actions never undo progress, which gives a relaxed problem that is much easier to solve.

Planners using relaxed-problem heuristics, such as Fast Forward, made forward search highly effective.

The same relaxation trick that gives heuristics for puzzles gives heuristics for any planning domain.

Planning Graphs

A planning graph alternates levels of facts and actions, approximating which facts could become true after each number of steps. It provides accurate heuristic estimates, and the GraphPlan algorithm extracts plans directly from it.

Beyond Classical Planning

Real-world planning adds time, resources, uncertainty and hierarchy. Hierarchical task networks decompose high-level tasks into subtasks, much as people plan a trip before booking each step.

Closing Thought

Classical planning shows the value of describing actions explicitly. Once preconditions and effects are visible to the planner, it can reason about which actions matter and estimate how far it is from the goal.
