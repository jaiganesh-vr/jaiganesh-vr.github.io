NP-Completeness

Algorithms Complexity

Sep 26, 2026

Every algorithm in these notes runs in polynomial time. Many important problems, however, have no known polynomial-time algorithm, and NP-completeness theory explains why we suspect none exists. Recognising an NP-complete problem tells you to stop looking for a perfect, fast algorithm and choose a different strategy.

Decision Problems

The theory is framed in terms of decision problems, which have yes or no answers. Instead of asking for the shortest route, we ask whether there is a route of length at most k. An optimization problem is at least as hard as its decision version, so hardness results carry over.

P and NP

  • P: problems that can be solved in polynomial time, such as sorting, shortest paths and minimum spanning trees.
  • NP: problems where a proposed yes-answer, called a certificate, can be verified in polynomial time.

Every problem in P is in NP. Whether P = NP is the most famous open question in computer science.

For problems in NP, checking an answer is easy. Finding one may not be.

An Example: Subset Sum

Given a set of integers and a target t, is there a subset that adds up to exactly t?

Verifying is easy: given a candidate subset, add it up. Solving appears hard: the obvious method tries all 2ⁿ subsets. 

from itertools import combinations

# Verifying a certificate: polynomial time, O(n)
def verify(numbers, target, subset):
    return set(subset) <= set(numbers) and sum(subset) == target

# Finding a solution: exponential time, O(2^n · n)
def solve(numbers, target):
    for size in range(len(numbers) + 1):
        for subset in combinations(numbers, size):
            if sum(subset) == target:
                return subset
    return None

numbers = [3, 34, 4, 12, 5, 2]
print(solve(numbers, 9))              # (4, 5)
print(verify(numbers, 9, (4, 5)))     # True

With 6 numbers, the search checks at most 64 subsets. With 60 numbers it could need over a quintillion, while verifying any one answer still takes microseconds.

Reductions

A reduction transforms instances of problem A into instances of problem B in polynomial time, such that the answers match. If A reduces to B, then B is at least as hard as A: a fast algorithm for B would give a fast algorithm for A.

NP-Hard and NP-Complete

  • NP-hard: every problem in NP reduces to it.
  • NP-complete: NP-hard and also in NP.

The Cook-Levin theorem showed that Boolean satisfiability, SAT, is NP-complete. Since then, thousands of problems have been proved NP-complete by reducing a known NP-complete problem to them: 3-SAT, clique, vertex cover, Hamiltonian cycle, travelling salesperson and subset sum among them.

If any NP-complete problem had a polynomial-time algorithm, every problem in NP would, and P would equal NP.

What To Do in Practice

  • Small inputs: exact exponential algorithms are fine.
  • Special structure: subset sum has a pseudo-polynomial dynamic programming solution, O(n·t), practical when t is small.
  • Approximation: some problems, like metric TSP and vertex cover, have polynomial algorithms with provable error bounds.
  • Heuristics and solvers: local search, SAT solvers and integer programming solve many large real instances well, despite the worst case.

Closing Thought

NP-completeness is a map of where efficient algorithms probably do not exist. Knowing a problem's place on that map saves the effort of searching for the impossible and points toward approaches that work.
