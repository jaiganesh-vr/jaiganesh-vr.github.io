Hash Tables

Algorithms Data Structures

Aug 14, 2021

Dictionaries, sets, caches and database indexes all need fast insert, search and delete. Hash tables provide all three in expected constant time, which makes them one of the most widely used data structures.

Direct Addressing

If keys are small integers, we can use them as array indexes and get true O(1) operations. But most key universes, such as all possible strings, are vast, while only a few keys are stored. An array indexed by every possible key is impossible.

Hashing

A hash table uses a much smaller array of m slots and a hash function h(k) that maps each key to a slot. Two keys mapping to the same slot is a collision. Collisions are unavoidable when there are more possible keys than slots, so the design is about handling them well.

Chaining

With chaining, each slot holds a linked list of the keys that hash to it. Insert adds to a list; search scans one list.

The load factor α = n/m is the average number of keys per slot. Under the assumption that keys hash uniformly, a search takes Θ(1 + α) expected time. Keeping m proportional to n keeps α constant, so operations are O(1) on average.

Hash tables are fast on average, not in the worst case. Everything rests on the hash function spreading keys evenly.

Hash Functions

  • Division method: h(k) = k mod m, with m a prime not close to a power of 2.
  • Multiplication method: h(k) = ⌊m · (kA mod 1)⌋ for a constant 0 < A < 1, which works with any m.
  • Universal hashing: choose the hash function at random from a family, so no fixed input can reliably cause collisions. This protects against adversarial inputs.

Open Addressing

Open addressing stores every key in the table itself. On a collision, it probes other slots in a fixed sequence until it finds an empty one:

  • Linear probing: try h(k), h(k) + 1, h(k) + 2, … Simple and cache friendly, but long clusters form.
  • Quadratic probing: step sizes grow quadratically, reducing clustering.
  • Double hashing: a second hash function sets the step size, giving the best spread.

With load factor α < 1, an unsuccessful search makes at most about 1/(1 − α) expected probes. At α = 0.5 that is two probes; at 0.9, ten. Deletion is awkward, since removing a key can break probe sequences, so deleted slots are marked rather than emptied.

Resizing

When the load factor grows too high, the table is resized, typically doubled, and every key is re-inserted. A single resize costs O(n), but spread across all insertions, the amortised cost per insert stays O(1).

Closing Thought

Hash tables trade order for speed: they cannot return keys in sorted order or find ranges efficiently. For everything else, they are usually the right default.
