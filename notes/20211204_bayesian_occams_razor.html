Bayesian Occam's Razor

Machine Learning Bayesian Inference

Dec 04, 2021

A more flexible model always fits the training data at least as well as a simpler one, so training fit cannot be how we choose between them. Bayesian inference has a built-in answer: the simplest model that explains the data tends to win, with no separate complexity penalty added by hand.

The Marginal Likelihood

To compare models, apply Bayes' rule one level up. Given equal prior belief in each model, we prefer the one with the higher evidence, or marginal likelihood:

P(D | M) = ∫ P(D | θ, M) · P(θ | M) dθ

This is the average fit over all parameter values the model considers plausible. It is different from maximum likelihood, which scores a model by its single best parameter setting.

Why Simplicity Wins

P(D | M) is a probability distribution over possible datasets, so it must sum to one. This is the key point.

  • A simple model can only generate a small set of datasets, so it gives each of them high probability.
  • A flexible model can generate many datasets, so it must spread its probability thinly across them.

If the data could be explained by either, the simple model gives it higher probability simply because it made a sharper prediction.

Flexibility is paid for out of a fixed budget of probability.

A Worked Example

We flip a coin 10 times and see one particular sequence with 7 heads. Compare two models:

  • M₀: the coin is fair.
  • M₁: the coin has unknown bias θ, with a uniform prior.

The evidence for each is:

P(D | M₀) = (1/2)¹⁰ = 1/1024

P(D | M₁) = ∫ θ⁷ (1 − θ)³ dθ = 7! · 3! / 11! = 1/1320

M₁ at its best setting, θ = 0.7, gives likelihood 0.00222, more than double M₀'s 0.00098. Yet its evidence is lower, because most values of θ fit the data poorly and they count too. The Bayes factor of M₁ against M₀ is about 0.78, which leans slightly toward the fair coin. 

from math import exp, lgamma, log

def log_beta(a, b):
    return lgamma(a) + lgamma(b) - lgamma(a + b)

def bayes_factor(heads, flips):
    """Evidence for an unknown bias against a fair coin."""
    tails = flips - heads
    return exp(log_beta(heads + 1, tails + 1) - flips * log(0.5))

print(bayes_factor(7, 10))    # 0.78: favours the fair coin
print(bayes_factor(70, 100))  # 427:  strongly favours a biased coin

More data changes the verdict. With 70 heads in 100 flips, the same proportion, the fair coin can no longer account for the result, and the Bayes factor swings to around 427 in favour of a biased coin.

The BIC Approximation

The integral is often intractable. For large n it can be approximated by the Bayesian information criterion, where k is the number of parameters:

log P(D | M) ≈ log P(D | θ̂) − (k/2) · log n

This makes the idea explicit: best fit, minus a penalty that grows with both parameters and data.

A Caution About Priors

Parameter inference is often robust to the prior, because enough data overwhelms it. The marginal likelihood is not. Making a prior vaguer spreads probability more thinly and lowers the evidence, even if the predictions hardly change. Improper priors leave it undefined altogether. Priors need real thought when comparing models.

Closing Thought

Occam's razor is usually stated as a preference added from outside. In Bayesian model comparison it follows from probabilities summing to one. A model is rewarded for what it predicted, and it pays for everything else it could have predicted.
