Sorting in Linear Time

Algorithms Sorting

Feb 27, 2021

Merge sort, heapsort and quicksort all run in Θ(n lg n) at best. That is not a coincidence: no algorithm that sorts only by comparing elements can do better. Breaking the barrier requires exploiting something about the keys themselves.

The Lower Bound

Any comparison sort can be modelled as a decision tree. Each internal node is a comparison, and each leaf is a final ordering. To sort every input correctly, the tree must have at least n! leaves, one for each permutation.

A binary tree with n! leaves has height at least lg(n!), which is Θ(n lg n). The height is the worst-case number of comparisons.

Every comparison sort needs Ω(n lg n) comparisons in the worst case.

Counting Sort

If keys are integers in a small range 0 to k, we can count instead of compare: 

def counting_sort(a, k):
    count = [0] * (k + 1)
    for x in a:
        count[x] += 1
    for i in range(1, k + 1):        # prefix sums: final positions
        count[i] += count[i - 1]
    out = [0] * len(a)
    for x in reversed(a):            # reversed keeps it stable
        count[x] -= 1
        out[count[x]] = x
    return out

It runs in Θ(n + k), linear when k = O(n). Crucially, it is stable: equal keys keep their original order.

Radix Sort

Radix sort handles larger keys by sorting digit by digit, starting from the least significant digit, using a stable sort such as counting sort for each pass.

Stability is what makes this work: after sorting by the tens digit, elements with equal tens digits stay in the order the ones-digit pass left them.

For n numbers with d digits each in base k, radix sort takes Θ(d(n + k)). Sorting a million 32-bit integers as four 8-bit digits takes four linear passes.

Bucket Sort

Bucket sort assumes keys are uniformly distributed over an interval, such as [0, 1). It divides the interval into n equal buckets, places each element in its bucket, sorts each bucket with insertion sort, and concatenates them.

With uniform input, buckets stay small and the expected time is Θ(n). With skewed input, many elements can land in one bucket and performance degrades.

The Trade-off

  • Linear sorts depend on assumptions about keys: small integer ranges, fixed digit lengths or known distributions.
  • They often need extra memory, unlike in-place comparison sorts.
  • Comparison sorts work on anything that can be compared, which is why they remain the default.

Closing Thought

The n lg n bound is a limit on comparing, not on sorting. When keys carry exploitable structure, sorting can be as fast as reading the input.
