Binary Search Trees

Algorithms Data Structures

Feb 26, 2022

Hash tables give fast lookup but no order. Binary search trees keep keys ordered, supporting search, minimum, maximum, successor and range queries, all in time proportional to the height of the tree.

The BST Property

Each node holds a key and pointers to a left and right child. For every node x:

  • Keys in x's left subtree are ≤ x.key.
  • Keys in x's right subtree are ≥ x.key.

An inorder traversal, left subtree, then node, then right subtree, visits the keys in sorted order in Θ(n) time.

Searching and Inserting

Search starts at the root and goes left or right depending on the comparison, just like binary search. 

class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def search(node, key):
    while node is not None and key != node.key:
        node = node.left if key < node.key else node.right
    return node

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root

Both follow a single path down the tree, so they take O(h) time, where h is the height.

Minimum, Maximum and Successor

The minimum is found by following left pointers to the end; the maximum by following right pointers. The successor of a node is the minimum of its right subtree, or, if it has none, the lowest ancestor whose left child is also an ancestor.

Deletion

Deleting node z has three cases:

  • No children: remove it.
  • One child: replace z with its child.
  • Two children: find z's successor y, the minimum of its right subtree, and move y into z's position.

The two-child case is the subtle one, but it still runs in O(h).

Height Is Everything

Every operation is O(h). The whole question is how tall the tree gets.

If keys are inserted in random order, the expected height is O(lg n), and every operation is fast. If they are inserted in sorted order, each new key becomes the right child of the previous one, and the tree degenerates into a linked list of height n.

Real inputs are often partly sorted, so plain BSTs are risky. Balanced trees, such as red-black trees and AVL trees, rebalance on insertion and deletion to guarantee height O(lg n).

Closing Thought

The binary search tree is simple and versatile, but its performance depends on its shape. Balanced variants keep the same interface while removing that risk, which is the subject of the next note.
