Quicksort

Algorithms Sorting

Sep 12, 2020

Quicksort has a worst-case running time of Θ(n²), worse than merge sort or heapsort. Yet it is often the fastest sorting algorithm in practice. Understanding why requires looking at both its average-case behavior and its constant factors.

The Idea

Quicksort is divide and conquer with the work done before the recursion:

  • Divide: choose a pivot and partition the array so that elements smaller than the pivot come before it and larger ones after it.
  • Conquer: recursively sort the two parts.
  • Combine: nothing to do; the array is already sorted in place.

Partitioning

The Lomuto partition scheme uses the last element as the pivot and sweeps once through the array: 

import random

def partition(a, lo, hi):
    pivot = a[hi]
    i = lo - 1
    for j in range(lo, hi):
        if a[j] <= pivot:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[hi] = a[hi], a[i + 1]
    return i + 1

def quicksort(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo < hi:
        r = random.randint(lo, hi)        # random pivot
        a[r], a[hi] = a[hi], a[r]
        p = partition(a, lo, hi)
        quicksort(a, lo, p - 1)
        quicksort(a, p + 1, hi)

Partitioning takes Θ(n) time and no extra memory.

Best and Worst Cases

  • Best case: the pivot always splits the array evenly. T(n) = 2T(n/2) + Θ(n) = Θ(n lg n).
  • Worst case: the pivot is always the smallest or largest element, so one side is empty. T(n) = T(n − 1) + Θ(n) = Θ(n²).

With the last element as pivot, an already sorted array triggers the worst case, which is a realistic input.

Randomisation

Choosing the pivot at random makes the worst case extremely unlikely for any input. The expected running time of randomised quicksort is Θ(n lg n). Even a consistently lopsided split, such as 9 to 1, still gives O(n lg n), because the recursion depth stays logarithmic.

Randomisation moves the risk from the input, which you don't control, to the coin flips, which average out.

Why It Is Fast in Practice

  • Its inner loop is simple, with few operations per element.
  • It works in place and accesses memory sequentially, which suits caches.
  • Practical versions use median-of-three pivots, switch to insertion sort for small subarrays, and handle many equal keys with three-way partitioning.

Introsort, used in several standard libraries, starts with quicksort and falls back to heapsort if the recursion gets too deep, guaranteeing O(n lg n).

Closing Thought

Quicksort shows the gap between worst-case theory and practical performance. With a random pivot, its bad cases become so improbable that its speed on typical inputs is what counts.
