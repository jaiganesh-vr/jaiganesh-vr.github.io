Divide and Conquer

Algorithms Design Techniques

Mar 23, 2019

Divide and conquer is one of the most powerful algorithm design techniques. Many of the fastest known algorithms, from sorting to multiplying matrices, follow its pattern.

The Three Steps

  • Divide: split the problem into smaller subproblems of the same kind.
  • Conquer: solve the subproblems recursively. If they are small enough, solve them directly.
  • Combine: merge the subproblem solutions into a solution for the original problem.

Merge Sort

Merge sort divides an array into two halves, sorts each half recursively, then merges the two sorted halves. 

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    return merge(left, right)

def merge(left, right):
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

The merge step does the real work. Because both halves are already sorted, it repeatedly takes the smaller front element, in linear time.

Analysing It

Divide-and-conquer algorithms are analysed with recurrences. Merge sort makes two recursive calls on halves and spends linear time merging:

T(n) = 2T(n/2) + Θ(n)

The recursion tree has lg n levels, and each level does Θ(n) total work, so T(n) = Θ(n lg n). That beats insertion sort's Θ(n²) worst case by a wide margin for large inputs.

The work is spread evenly across levels, and there are only logarithmically many levels.

Another Example: Maximum Subarray

Given an array of numbers, find the contiguous subarray with the largest sum. Divide and conquer splits the array in half; the best subarray is either entirely in the left half, entirely in the right half, or crosses the midpoint. The crossing case is found in linear time by extending outward from the middle. The result is again Θ(n lg n).

When It Helps

  • Subproblems should be independent. If they overlap heavily, dynamic programming is better.
  • The combine step should be cheap relative to the savings from splitting.
  • Recursion adds overhead, so practical implementations often switch to a simple method for small inputs.

Closing Thought

Divide and conquer turns big problems into many small ones that are easy to solve. Its running time comes down to a recurrence, which the master method in the next note solves for most common cases.
