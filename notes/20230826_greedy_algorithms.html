Greedy Algorithms

Algorithms Design Techniques

Aug 26, 2023

A greedy algorithm makes the choice that looks best right now and never reconsiders it. That is simpler and faster than dynamic programming, which weighs every option. The catch is that greedy choices only lead to an optimal solution for certain problems.

When Greedy Works

Greedy algorithms are correct when a problem has two properties:

  • Greedy-choice property: a globally optimal solution can be reached by making a locally optimal choice first.
  • Optimal substructure: after making that choice, the remaining problem is a smaller instance of the same problem.

Proving the greedy-choice property is the essential step. A common technique is the exchange argument: take any optimal solution and show it can be modified to include the greedy choice without getting worse.

Activity Selection

Given activities with start and finish times, select the largest set of non-overlapping activities.

The greedy rule: always pick the activity that finishes earliest, then repeat with the activities that start after it. 

def select_activities(activities):
    chosen, last_finish = [], float("-inf")
    for start, finish in sorted(activities, key=lambda a: a[1]):
        if start >= last_finish:
            chosen.append((start, finish))
            last_finish = finish
    return chosen

Finishing earliest leaves the most room for everything else. After sorting, this takes linear time.

Greedy works when one good local decision never closes off a better global outcome.

Huffman Codes

Huffman coding builds an optimal prefix-free binary code for compressing data. Frequent characters get short codes, rare ones long codes.

The greedy step: repeatedly merge the two least frequent nodes into a new node whose frequency is their sum. Using a priority queue, this runs in O(n lg n) for n characters. Huffman coding is part of formats such as DEFLATE, used in ZIP and PNG.

Knapsack: Where Greedy Fails

In the fractional knapsack problem, items can be split. Taking items in order of value per unit weight is optimal.

In the 0-1 knapsack problem, items must be taken whole. The same greedy rule can fail: a high-ratio item may leave unused capacity that a combination of other items would have filled better. The 0-1 version needs dynamic programming.

Other Greedy Algorithms

Several fundamental graph algorithms are greedy: Prim's and Kruskal's algorithms for minimum spanning trees, and Dijkstra's algorithm for shortest paths. Each relies on a property guaranteeing that its local choice is safe.

Closing Thought

Greedy algorithms are often the simplest and fastest solution, but they require proof. The difference between fractional and 0-1 knapsack shows how a small change to a problem can make the greedy approach fail.
