Naive Bayes Classifiers

Machine Learning Generative Models

Mar 12, 2022

Naive Bayes is often introduced as a spam filter, but it is really a family of classifiers. Each member follows the same recipe of modelling how features are generated within each class, then inverting with Bayes' rule.

Generative Classification

A generative classifier learns the joint distribution through two parts:

P(y = c | x) ∝ P(y = c) · P(x | y = c)

The class-conditional density P(x | y) is the hard part. A full model over d binary features needs on the order of 2ᵈ parameters per class. Naive Bayes assumes that features are conditionally independent given the class:

P(x | y = c) = Π P(xⱼ | y = c)

The parameter count falls from exponential in d to linear in d.

Choosing the Feature Model

The factorisation leaves each P(xⱼ | y) free to fit the data type:

  • Bernoulli: binary features, such as whether a word occurs in a document at all.
  • Multinomial: counts, such as how many times each word occurs. This is usually the better choice for longer documents.
  • Gaussian: continuous features, with a mean and variance per feature per class.

The maximum likelihood estimates are simple class-wise averages, so training takes one pass over the data. 

import numpy as np

def fit(X, y):
    classes = np.unique(y)
    prior = np.array([(y == c).mean() for c in classes])
    mean = np.array([X[y == c].mean(axis=0) for c in classes])
    var = np.array([X[y == c].var(axis=0) + 1e-9 for c in classes])
    return classes, prior, mean, var

def predict(X, classes, prior, mean, var):
    # Log joint for each class: prior plus one Gaussian term per feature
    log_lik = -0.5 * (np.log(2 * np.pi * var) + (X[:, None] - mean)**2 / var)
    return classes[np.argmax(np.log(prior) + log_lik.sum(axis=2), axis=1)]

rng = np.random.default_rng(0)
X = np.vstack([rng.normal(0, 1, (200, 2)), rng.normal(3, 1, (200, 2))])
y = np.repeat([0, 1], 200)
print((predict(X, *fit(X, y)) == y).mean())

Smoothing as a Prior

Maximum likelihood gives zero probability to anything unseen, and a single zero wipes out the whole product. Placing a Dirichlet prior on the word probabilities and taking the posterior mean adds α pseudo-counts to each word:

P(word | c) = (count(word, c) + α) / (total(c) + α · V)

Laplace smoothing is the special case α = 1, with V the vocabulary size.

The Decision Boundary

For Bernoulli and multinomial features, the log-odds between two classes is a sum of per-feature terms, which is linear in the features:

log P(y = 1 | x) / P(y = 0 | x) = wᵀx + b

So naive Bayes draws the same kind of boundary as logistic regression. The difference is how the weights are set. Naive Bayes fits each feature separately, while logistic regression fits them jointly to the classification objective.

Generative or Discriminative

Ng and Jordan compared the two in a well-known 2001 paper:

  • With little data: naive Bayes often wins, approaching its best error with far fewer examples.
  • With plenty of data: logistic regression usually wins, having a lower error in the limit because it is not bound by the independence assumption.

Why It Works Despite Being Wrong

Correlated features get counted repeatedly, which drives the probabilities toward 0 or 1. Classification only needs the correct class to score highest, so the ranking can be right even when the probabilities are not. If you need calibrated probabilities, recalibrate them or use another model.

Closing Thought

Naive Bayes trades accuracy of assumptions for a large reduction in variance. If we let features within a class be correlated, using a Gaussian with a full covariance, we arrive at Gaussian discriminant analysis.
